AGET Framework Vocabulary

Published concepts from the AGET framework — configuration and lifecycle management for CLI-based human-AI collaborative coding agents.

Learning Document

https://w3id.org/aget/vocab#Learning_Document

A structured, persistent, searchable document that captures a single durable lesson extracted from operational experience, classified for reuse either by other agents (framework lessons) or by the human principal (domain lessons). Functions as a unit of organizational memory that persists beyond ephemeral session context; designed for accretion — many small cross-linked documents rather than monolithic reports.

Example: An agent records a lesson that publication-forum decisions are not publication- standard adoptions, and later sessions cite it before designing a publishing capability.

related: Software_Session

Forum page: https://www.gabormelli.com/RKB/Learning_Document

Agent Fleet

https://w3id.org/aget/vocab#Agent_Fleet

A bounded set of software agents operating under shared governance, typically with one supervising agent and multiple worker agents. A fleet shares configuration standards, session protocols, and a common upgrade lifecycle while each member retains its own domain scope and memory.

Example: A fleet supervisor coordinates version upgrades across its worker agents and verifies each member's deployment before closing a release cycle.

related: Initialization_Protocol

Forum page: https://www.gabormelli.com/RKB/Agent_Fleet

Software Session

https://w3id.org/aget/vocab#Software_Session

A bounded interval of interactive or autonomous software operation with a defined start and end, its own working context, and lifecycle protocols that establish and wind down that context. For collaborative agents, the session is the unit within which context is loaded, work is performed, and durable artifacts are handed off.

Example: An agent session opens with an initialization protocol that loads identity and pending work, and closes by writing a handoff file for the next session.

related: Initialization_Protocol · related: Learning_Document

Forum page: https://www.gabormelli.com/RKB/Software_Session

Initialization Protocol

https://w3id.org/aget/vocab#Initialization_Protocol

A defined startup ritual that loads an agent's identity, version, governing constraints, and pending work into operating context before substantive work begins. Ensures each operating interval starts from verified state rather than assumptions; the counterpart termination protocol performs structured closure and handoff.

Example: On "wake up", an agent runs its initialization protocol: read identity and version, verify governance is loaded, list active work, report readiness.

related: Software_Session

Forum page: https://www.gabormelli.com/RKB/Initialization_Protocol

Verification Test

https://w3id.org/aget/vocab#Verification_Test

An executable check paired with a requirement or deliverable that returns pass or fail, distinguishing verified completion from declared completion. Verification tests gate stage boundaries: work is complete when its test passes, not when its author asserts completion.

Example: A release gate requires each advertised capability to pass its verification test — an executable command whose output confirms the artifact exists and behaves as claimed — before the release tag is created.

Forum page: https://www.gabormelli.com/RKB/Verification_Test

Aget Agent

https://w3id.org/aget/vocab#Aget_Agent

A configured software agent instance built on the AGET framework, combining an identity (purpose, scope, governing constraints), persistent memory, skill-based capabilities, and session lifecycle protocols. Instantiated from an agent template repository and operated in collaboration with a human principal who holds decision authority over irreversible acts.

Example: A framework-manager agent instance that stewards a public repository: it wakes with its identity and pending work, executes gated plans, and records lessons for future sessions.

related: Agent_Fleet · related: Agent_Template_Repository

Termination Protocol

https://w3id.org/aget/vocab#Termination_Protocol

A defined closure ritual that ends an agent's operating interval in a recoverable state: verifying health, capturing pending work, recording session artifacts, and preparing handoff context so the next interval can resume without loss. The counterpart of an initialization protocol.

Example: On "wind down", an agent checks for uncommitted changes and open plans, writes a session summary with handoff notes, and reports what the next session should pick up.

related: Initialization_Protocol · related: Software_Session

Agent Capability

https://w3id.org/aget/vocab#Agent_Capability

A named, scoped, testable ability of a software agent, expressed as formal requirements with executable verification. Distinct from a capability measure (an assessment of how well a system performs): an agent capability is a specified, versioned artifact whose presence and behavior can be verified by test rather than asserted.

Example: A session-management capability specified as requirements with paired verification tests, such that an upgrade can prove the capability still holds before deployment.

related: Verification_Test

Agent Template Repository

https://w3id.org/aget/vocab#Agent_Template_Repository

A published, version-controlled repository defining an agent archetype from which agent instances are instantiated, carrying baseline skills, capabilities, session protocols, and governance configuration. Distinct from an agent design pattern (a reusable architectural solution): a template repository is an instantiable artifact with a version lifecycle.

Example: A developer archetype repository that new coding agents are created from, inheriting its session protocols and baseline skills, then diverging with instance-specific memory and scope.

related: Aget_Agent

Agent Skill

https://w3id.org/aget/vocab#Agent_Skill

A named, documented, invocable unit of agent procedure — instructions, constraints, and optional supporting scripts — that an agent loads on demand to perform a recurring task in a governed way. Skills are versioned artifacts with declared triggers, distinct from the agent's ambient instructions: they encapsulate one procedure behind one name.

Example: A record-lesson skill that an agent invokes to capture a durable learning with consistent structure, classification, and traceability.

related: Slash_Command · related: Agent_Capability

Slash Command

https://w3id.org/aget/vocab#Slash_Command

A user-invocable command addressed by a leading slash (such as /review or /deploy) inside a chat, CLI, or agent interface, mapping a short memorable name to a defined procedure or prompt. In agentic coding tools, slash commands are the common invocation surface for agent skills.

Example: Typing /wake-up in an agent CLI invokes the session initialization skill; typing /review in a chat tool triggers a code review procedure.

related: Agent_Skill

Software Hook

https://w3id.org/aget/vocab#Software_Hook

A defined extension point at which a software system invokes externally supplied code in response to a lifecycle event, allowing behavior to be added or intercepted without modifying the host system. In agent frameworks, hooks fire on events such as session start or before tool execution, and are the structural surface for tracing and access control.

Example: A pre-tool-use hook that logs each consultation and denies callers not on an allowlist, enforcing policy even when higher-level configuration is inert.

related: Agent_Skill

Executable Knowledge Ontology

https://w3id.org/aget/vocab#Executable_Knowledge_Ontology

A structured vocabulary that classifies knowledge artifacts by how executable they are, organizing them along axes such as abstraction level (from algorithm to concrete execution), determinism, and reusability. Bridges documentation and automation: entries are classified by whether a machine can act on them directly, with parameters, or only via human interpretation.

Example: Classifying a deployment procedure as parameterized-executable (a script with inputs) versus a design rationale as human-interpretable knowledge.

related: Learning_Document

Session Protocol

https://w3id.org/aget/vocab#Session_Protocol

A defined, repeatable procedure governing a phase of a software session's lifecycle — initialization, checkpointing, health verification, or termination — so that session state transitions are performed by rule rather than improvisation.

Example: An agent's session protocols include a wake-up procedure, a mid-session checkpoint save, and a wind-down closure with handoff.

broader: Software_Session · related: Initialization_Protocol · related: Termination_Protocol

Software Specification

https://w3id.org/aget/vocab#Software_Specification

A contract-level document that formalizes intended software behavior as testable, enforceable requirements, typically in a controlled syntax with unique requirement identifiers and paired verification tests. In a two-level model, specifications formalize human-level requirements; when behavior fails, the specification is examined first, since code can correctly implement a wrong specification.

Example: A session-lifecycle specification whose requirements each carry an identifier, a controlled-syntax statement, and an executable verification test.

related: Verification_Test · related: Agent_Capability

AGET Framework

https://w3id.org/aget/vocab#AGET_Framework

A configuration and lifecycle management framework for CLI-based human-AI collaborative coding agents, providing agent identity, persistent memory, skill- based capabilities, session protocols, template repositories, and governance constraints with approval gates. Distributed as a public reference implementation with instantiable agent templates.

Example: An engineer instantiates a worker agent from an AGET template, and the agent thereafter wakes, works within gated plans, records lessons, and winds down under the framework's session protocols.

Ontology CI Gate

https://w3id.org/aget/vocab#Ontology_CI_Gate

A check that runs a controlled vocabulary's quality validators automatically on every proposed change, and blocks the change from being merged when a validator reports a defect. Without it, validation depends on someone remembering to run it, so a vocabulary can accumulate defects indefinitely while each individual change is believed to have been checked — the belief and the measurement drift apart with nothing to reconcile them.

Example: A project keeps a link validator in its repository and runs it by hand at the end of each expansion cycle. Between cycles the vocabulary is unmeasured, and a defect introduced early is found only when someone next remembers. Wiring the same validator into the merge check converts the measurement from a habit into a precondition.

Denominator Disclosure

https://w3id.org/aget/vocab#Denominator_Disclosure

The obligation to state the population a rate or count was computed over, at the point the figure is asserted. Naming the instrument that produced a number answers how it was measured but never what it was measured over, and the two diverge silently. An instrument can be correct and still range over the wrong set, yielding a figure that is precise, reproducible and wrong — and undetectably so, because nothing in the figure records the set it came from.

Example: A census of managed agents taken by directory pattern returned four different totals on four occasions, each defensible from its own listing and none matching the authoritative register. The instrument was not at fault. No figure had stated the set it ranged over, so no two of them could be compared, and the disagreement went unnoticed.

related: Author_Asserted_Cleanliness_Anti_Pattern

Reciprocal Link Validator

https://w3id.org/aget/vocab#Reciprocal_Link_Validator

A validator that checks whether the associative and hierarchical links in a concept scheme are declared symmetrically: that every concept named as related by another names it in return, and that every broader link has a matching narrower link on the parent it points to. It exists to catch the dominant failure mode of vocabularies maintained by addition, where a new concept is linked forward to existing ones and the corresponding edits to those existing ones are never made.

Example: An author adds a concept and lists six existing concepts as related to it. Unless each of those six is also edited, the vocabulary asserts the relationship in one direction only, and a reader arriving from any of the six will never reach the new concept.

related: Ontology_CI_Gate · related: Forward_Only_Link_Defect · related: Author_Asserted_Cleanliness_Anti_Pattern · related: Reflexive_Validation_Methodology

Forward-Only Link Defect

https://w3id.org/aget/vocab#Forward_Only_Link_Defect

A defect in a concept scheme where a link between two concepts is declared in one direction only, because the author edited the concept being added and not the existing concepts it points at. The defect is invisible from the concept that was authored, where the work looks finished, and shows up only when the vocabulary is read from the other end. That asymmetry of visibility is why it accumulates rather than being caught.

Example: Across six consecutive expansion cycles of one vocabulary, links between concepts in the same cluster were made symmetric while being written, and links crossing clusters were deferred to a cleanup that was never scheduled. The deferred edits grew into the vocabulary's single largest defect class.

related: Reciprocal_Link_Validator

Fail-Stop Behavior

https://w3id.org/aget/vocab#Fail_Stop_Behavior

A failure semantics in which a faulty component halts before producing any externally visible erroneous output, so that other components can reliably detect the failure and begin recovery. It is the strongest well-behaved failure class — detectable and non-contagious — and the property that makes a missing component safe: a check that cannot run must report that it could not run, because a silent absence reads as success.

Example: An agent meeting unambiguously corrupted state halts cleanly instead of continuing and emitting plausible output derived from it. A supervisor can then trust that a halted worker sent nothing downstream. The contrasting case is arbitrary behavior, where a faulty component keeps producing output that cannot be distinguished from correct output.

related: Failure_Detector

Failure Detector

https://w3id.org/aget/vocab#Failure_Detector

An abstract oracle in a distributed system that gives each process suspicion information about the others, classified by completeness (every crashed process is eventually suspected) and accuracy (correct processes are not suspected). Chandra and Toueg showed that the eventually-strong class is the weakest one that can solve consensus given a majority of correct processes, which sets a hard limit on what any supervisor can know about a worker it cannot see.

Example: Heartbeat-based liveness checking is inherently unreliable: a timeout cannot separate a crashed process from a slow one. Any liveness claim therefore carries a false-positive rate, and an escalation policy has to handle that rate rather than assume it away.

related: Fail_Stop_Behavior

Author-Asserted Cleanliness Anti-Pattern

https://w3id.org/aget/vocab#Author_Asserted_Cleanliness_Anti_Pattern

A failure mode in which an author, or a tool acting on their behalf, reports a vocabulary or artifact as free of defects on the strength of confidence rather than validator output. The harm is not that the claim is often wrong but that it is indistinguishable in form from a measured one, so it displaces the measurement it stands in for: a reader downstream treats an unmade claim as a verified one, and nothing in the record distinguishes them.

Example: A procedure ended with the author recording "no orphans, no dangling references, all links reciprocal". Replacing that line with a requirement to paste the validator's actual output changed the reported state on the very first run.

Reflexive Validation Methodology

https://w3id.org/aget/vocab#Reflexive_Validation_Methodology

A methodology for validating a vocabulary or a tool by turning it on itself — using the expansion procedure to expand the vocabulary that describes expansion, or the validation concepts to validate the validator. The reflexive case is diagnostic because it is the one case whose authors cannot argue is unrepresentative: a procedure that fails on its own subject matter has been falsified by the least contrived example available to it.

Example: A vocabulary was expanded with concepts describing validation, and its own validators were then run over the result. The defects that surfaced were in the validators' coverage rather than in the new concepts — a gap that expansions into unrelated domains had never exposed.
